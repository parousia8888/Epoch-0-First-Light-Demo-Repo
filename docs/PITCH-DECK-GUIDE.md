# PITCH-DECK-GUIDE · 一句话出 3 分钟 pitch deck

> 给 AI 助手的执行规范。用户说「做个 pitch deck / 做演示」时,照这份文档执行。
> 产出物:`deck/index.html` **单个自包含 HTML 文件**,浏览器全屏(F11)即演示,
> ←→ 翻页。不引外部库、不联网(Google Fonts 可用)。

## 流程(六步,前三步做对,后面全是参数调整)

### 1. 识别锚 → token(抽取,不是复刻)

锚在哪:
- 认领了某个 demo → **它的 `demos/<slug>/theme.ts` 和 polishHint 就是锚**。deck 必须长得像那个 demo 的世界(keigo 的 deck 是和纸信笺的,gomi 的 deck 是 8bit 的),不是长得像"一个 PPT"
- 做自己的产品 → 用他产品已有的品牌;什么都没有 → 用 Epoch 0 基调(近黑底、单强调色、等宽点缀)

从锚反推一套 token 写在 `:root` CSS 变量里:色板(底/墨/1-2 个信号色)、字体二元对立(标题一种人格、数据/代码一种等宽)、图形文法(这个世界用什么线条:朱印?像素框?表格线?)。
**同时写一份禁止清单**放在文件头注释里,和正面规范同等重要。默认禁:AI 渐变紫、玻璃拟态、无意义粒子、五颜六色、每页换布局。

### 2. 世界观 → 一个统摄隐喻

一句话定调(例:postmortem 的 deck 是"一份验尸报告"、roulette 的是"一台老虎机"),之后所有命名、动效语义、页面节奏都从它推导,不再逐页讨论。动效是"世界在运作",不是"页面在表演"——能删的动效都删。

### 3. 引擎先行,内容后置

先写骨架再填内容:一个 `<section>` = 一页;翻页 = 改 `data-page` 状态字,CSS 据此显隐;常驻 chrome(右下页码 `N / 5`、左下 `Epoch 0 · First Light Vol.1`)。内容是骨架上的薄层,这样反复增删页不散架。

### 4. 页面镜像 pitch 结构(固定五页,3 分钟刚好)

1. **名字 + 一句话**(大字裸奔,占满屏)
2. **痛点**(一个具体场景,不超过三行)
3. **现场演示**(deck 里只放一张截图 + 大号 URL/二维码,真演示切浏览器——deck 不替产品说话)
4. **我们动了什么**(认领 demo 的队:解锁了哪个坑,before 置灰 → after 能用;自研的队:今天从零到几)
5. **下一步 + 团队名**(一行方向 + 成员名,不写商业计划)

信息密度三档:大字页 / 行式清单页 / 一图页。一页只做一档。

### 5. 截图驱动迭代

每改一轮 → 浏览器截图 → 和第 1 步的锚(demo 页面截图/参考图)并排比 → 调参。渲染不对就二分定位,不猜。

### 6. 收敛靠减法

初版做全再删:3 分钟讲不到的页、读不完的字、解释性的小字,全删。克制是删出来的,不是设计出来的。

## 给 agent 的硬约束

- 从提问开始:先问用户「demo 页面/产品截图有吗?团队名?下一步一句话?」——第 3、5 页的素材只有用户知道
- 全程不超过 5 页;用户要加页,先问他删哪页
- 写完自己用浏览器开一遍、逐页截图检查再交付
- deck 提交进 git(`deck/` 目录),散场后它就是作品页的第一张截图素材
